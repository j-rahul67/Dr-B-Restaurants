# QSR Daily Demand — Stage 1 Project (Final candidate, Revision 13)

A focused Quarto website and reproducible R analysis for the OMIS 681 QSR Daily Demand assignment. This revision separates source-data information, data descriptions, a guided exploratory analysis, and the business report. The EDA page follows a step-by-step flow: inspect the data, establish quantity baselines, compare meaningful groups, create calendar context, and use course-aligned charts to examine distributions and relationships.

## Required inputs

Copy the eight required CSVs listed in `data/README.md` into `data/`. `restaurant_profile.csv` is supplied with the original bundle but is not needed for the Stage 1 questions selected here. The source CSVs are not included in this package. Copy the eight originals from your existing QSR dataset into data/ before rendering; do not commit source CSVs to public GitHub.

## Data-quality findings

The Data page reports missing sales quantities, duplicate date/item combinations, unmatched menu joins, invalid temperature codes, missing weather dates, and missing price/cost/preparation fields. The checks are recalculated from the original CSVs at render time. The initial review found 365 missing sales quantities (about 0.4%), zero duplicate date-item combinations, 14 temperature values coded as -99, and 55 Minneapolis calendar dates without a matching weather record. Missing quantities are excluded from item-day comparisons; -99 temperatures are treated as missing; weather values are not invented for uncovered dates.

## Run in RStudio

1. Extract the ZIP and copy the eight required source CSVs into `data/`.
2. Open `QSR_Stage1_Project.Rproj` in RStudio.
3. In the Console run `source("R/install_packages.R")`.
4. Run `source("R/check_project.R")`.
5. In the Terminal run `quarto render`.
6. Open `_site/index.html`; use **Analysis report** to read the scrolling report.

## Story and graphs

The report follows this flow: what sells, when demand changes, whether top products move together, how demand distributions differ under promotions, how unit volume compares with estimated food-cost margin, and whether weather, events, price, preparation time, or marketing show useful associations. Graphs use the Week 4–5 concepts supplied for the course: bar rankings, line charts, boxplots/violin plots, scatterplots with smoothing lines, correlation heatmaps, faceting, multiple geoms, and aesthetic mappings. EDA explains the exploratory steps and includes four purposeful charts: a histogram, grouped category bars, violin/boxplots, and faceted scatterplots with smoothing lines. It builds context for, rather than replaces, the business report.

All graphs are static `ggplot2` outputs. Each chart has a collapsible **Show R code** section with the exact R code used to create it. A small local script animates figures as they appear during scrolling; there are no Plotly controls or external chart-interaction dependencies.

## Scope and limitations

This is a Stage 1 descriptive analysis of one selected restaurant, R07 in Minneapolis. It excludes machine learning and avoids causal claims from observational relationships. Estimated food-cost margin applies listed prices and food costs to observed quantities and is not net profit or historical accounting.

Package setup note: Each Quarto document runs in its own R session. The EDA page independently loads `tidyverse` before using data-manipulation and plotting functions. Chart objects are now explicitly assigned and passed to `show_chart()` to prevent a theme object from printing instead of a graph. If packages are missing, run `source("R/install_packages.R")` from the project root.
